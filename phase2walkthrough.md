# Phase 2: Database Integration

I have successfully completed Phase 2 of the Meet Management project. The goal was to replace the local CSV file upload system with a SQLite database powered by SQLAlchemy.

## What was Changed

1. **Database Schema & ORM (`models.py`)**:
   - Created SQLAlchemy models for `Team`, `Swimmer`, `Meet`, `Entry`, and `RelayEntry`.
   - Setup relationships linking entries to swimmers and meets.

2. **Database Initialization (`database.py`)**:
   - Established the connection engine and session generator for SQLite (`meet_management.db`).

3. **Refactored Core Logic (`swimmer.py` and `meet.py`)**:
   - Updated `Swimmer` class to initialize directly from the database model object instead of a raw CSV string list.
   - Refactored `meet.py` to use `load_from_db(db, meet_id)` instead of parsing `swimmer_files` and `relay_files`.

4. **Updated API Endpoints (`api.py`)**:
   - Added RESTful GET endpoints (`/teams`, `/swimmers`, `/meets`) to read from the database.
   - Refactored `/generate` to expect a single `meet_id` form field instead of requiring CSV file uploads. It pulls the necessary records from the database to generate the heat sheet.

5. **Test Data Seeding (`seed.py`)**:
   - Created a seed script that parses the existing CSVs in `Data Files/` and populates the SQLite database.

6. **Docker Validation**:
   - Updated `requirements.txt` to include SQLAlchemy.
   - Successfully built the Docker image `meet-api` locally.

## Verification

The `seed.py` script was run locally to populate the test data. It successfully parsed the test files and inserted the records. A successful Docker build validates that the new dependencies (`SQLAlchemy`) and API entry point are working without errors.

> [!NOTE]
> Next time you start the Docker container, you can pass a `meet_id` (such as `meet_bBTjJHcX` which was generated by the seeder) to the `/generate` endpoint, and it will fetch all associated entries automatically.
